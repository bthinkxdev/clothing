# SECTION F: SPECIAL FLOWS & EDGE CASES

## 1. OTP Login Flow (Detailed)

### Step 1: Login Page
```
URL: /auth/login/
View: LoginView (TemplateView)
Template: auth/login.html

UI Elements:
- Phone number input (10 digits)
- Send OTP button
- Privacy policy checkbox
- Guest checkout option
```

### Step 2: Send OTP
```
URL: /auth/otp/send/ (AJAX POST)
View: OTPSendView

Process:
1. Validate phone number
2. Generate 6-digit OTP
3. Send via SMS gateway
4. Store in session with expiry (5 minutes)
5. Return success JSON

Response:
{
    'success': True,
    'message': 'OTP sent successfully'
}
```

### Step 3: Verify OTP
```
URL: /auth/otp/verify/ (AJAX POST)
View: OTPVerifyView

Process:
1. Get phone and OTP from request
2. Check against session data
3. Verify expiry
4. If valid:
   - Get or create user with phone
   - Login user
   - Clear session OTP data
   - Redirect to 'next' URL or home
5. If invalid:
   - Return error

Response:
{
    'success': True,
    'redirect': '/checkout/address/'
}
```

### Edge Cases Handled:
- **OTP Expiry:** After 5 minutes, show "OTP expired, resend"
- **Invalid OTP:** Show error, allow 3 attempts before requiring resend
- **Resend Limit:** Max 3 OTPs within 30 minutes
- **Phone Already Exists:** Auto-login existing user
- **Phone Not Registered:** Create new customer account
- **Return URL:** After login, redirect to previous page using 'next' parameter

## 2. Cart & Inventory Management Flow

### Adding to Cart
```python
Process:
1. Check variant is active
2. Check available stock (quantity - reserved)
3. If in stock:
   - Add to cart or increment quantity
   - Do NOT reserve inventory yet
4. If insufficient stock:
   - Add maximum available
   - Show warning message

Edge Cases:
- Out of stock: Disable add-to-cart, show "Notify Me"
- Low stock: Show "Only X left" badge
- Preorder variant: Allow add-to-cart, show "Preorder" badge
```

### Cart to Checkout
```python
Process:
1. User clicks "Proceed to Checkout"
2. Verify all cart items have stock
3. Reserve inventory for all items
4. Redirect to checkout/address

Edge Cases:
- Stock became unavailable: Remove item, show message
- Quantity exceeds stock: Reduce to available, show warning
```

### Checkout Abandonment
```python
Process (Background Task - Celery):
1. After 30 minutes of inactivity
2. Unreserve inventory
3. Mark cart as abandoned
4. Send reminder email after 24 hours

Cleanup:
- Unreserved inventory available for other customers
- Cart remains but not blocking inventory
```

### Order Placement
```python
Process:
1. Create order record
2. Create order items from cart
3. Reserve inventory for each item
4. Create payment record
5. If payment succeeds:
   - Deduct inventory permanently
   - Unreserve from reserved pool
   - Clear cart
6. If payment fails:
   - Keep order as 'pending'
   - Keep inventory reserved for retry
   - After 2 hours, unreserve and cancel order
```

## 3. Coupon Application Flow

### Apply Coupon
```python
URL: /checkout/apply-coupon/
View: ApplyCouponView (POST)

Validation:
1. Coupon code exists
2. Coupon is active
3. Within date range (start_date to end_date)
4. Cart value >= min_purchase_amount
5. Global usage limit not exceeded
6. User usage limit not exceeded
7. Product/category restrictions match cart items

Process:
1. Validate all conditions
2. Calculate discount amount
3. Store coupon code in session
4. Redirect to payment page

Edge Cases:
- Invalid code: "Coupon not found"
- Expired: "Coupon expired on [date]"
- Below minimum: "Add ₹X more to apply this coupon"
- Already used: "You've already used this coupon"
- Limit exceeded: "This coupon is no longer available"
```

### Remove Coupon
```python
URL: /checkout/remove-coupon/
View: RemoveCouponView (POST)

Process:
1. Remove from session
2. Recalculate totals
3. Redirect back
```

### Coupon Usage Record
```python
Created when:
- Order is successfully placed and paid

Record includes:
- Coupon
- User
- Order reference
- Timestamp

Used for:
- Tracking usage limits
- Preventing re-use
- Analytics
```

## 4. Multiple Payment Attempts

### Payment Failure Handling
```python
Scenario: Razorpay payment fails

Process:
1. Order created, status='pending'
2. Payment record created, status='failed'
3. Inventory remains reserved
4. User redirected to failure page
5. Options shown:
   - Retry with same method
   - Choose different method
   - Contact support

Retry Process:
1. Get existing order
2. Create new payment record
3. Initialize payment again
4. On success: Mark order paid
5. On failure: Keep order pending

Auto-Cancellation:
- After 2 hours of pending payment
- Unreserve inventory
- Change order status to 'cancelled'
- Send email notification
```

## 5. Guest Checkout → Login → Cart Merge

### Guest Cart Storage
```python
# Option 1: Session-based
request.session['guest_cart'] = {
    'items': [
        {'variant_id': 1, 'quantity': 2},
        {'variant_id': 5, 'quantity': 1},
    ]
}

# Option 2: Cookie-based
# For persistent guest carts across sessions
```

### Merge on Login
```python
Process (in OTPVerifyView):
1. User logs in successfully
2. Check for guest_cart in session
3. Get or create user's Cart
4. For each guest cart item:
   - Check if already in user cart
   - If yes: Update quantity (combine)
   - If no: Add new CartItem
5. Clear guest_cart from session

Edge Cases:
- Duplicate variants: Combine quantities
- Out of stock: Add available quantity only
- User cart + guest cart > stock: Cap at available
```

```
## 9. Order Cancellation Flow

### Customer-Initiated

URL: /orders/<uuid:id>/cancel/
View: OrderCancelView (POST)

Conditions:
- Order status in ['pending', 'processing']
- Not yet shipped

Process:
1. Check cancellation eligibility
2. Unreserve/restore inventory
3. Update order status to 'cancelled'
4. If payment made:
   - Initiate refund
   - Credit to wallet or original payment method
5. Send cancellation email

Edge Cases:
- Already shipped: Cannot cancel, show return option
- COD order: Just cancel, no refund needed
- Partial cancellation: Not supported (business rule)
```

## 10. Wallet Payment Flow

### Wallet Payment

Process:
1. Check wallet balance >= order total
2. Deduct from wallet balance
3. Create payment record (status='success')
4. Mark order as paid
5. Finalize order (deduct inventory)
6. Clear cart
7. Redirect to success page

Edge Cases:
- Insufficient balance: Show error, suggest other methods
- Race condition: Use F() expressions and transactions
```

### Wallet Top-Up

Process:
1. User selects amount
2. Initiate Razorpay payment
3. On success:
   - Credit to wallet_balance
   - Create transaction record
4. On failure:
   - Show error, allow retry
```
